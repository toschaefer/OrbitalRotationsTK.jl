Functionals and representations

rotate evaluates the loss and its gradient through a combination of two choices:

  • the functional, e.g. NPL: what is optimized. Functionals of the same form belong to one family, e.g. JointDiagonalizationFunctional, and share the numerics.
  • the representation, e.g. OrbitalSubspace, passed as rotate(...; representation): how the loss and its gradient are computed.

The cost and memory depend on the combination of family and representation. This page lists which combinations exist and how they scale.

Cost and memory

Symbols: $N$ orbitals, $N_F$ operators of the functional (e.g. atoms with nonzero weight in NPL), $N_G$ plane waves of the overlap densities (see Ecut_ratio), $N_r$ points of the FFT grid. The preparation runs once per call of rotate; the optimizer then evaluates the gradient a few times per iteration. All numbers are for the Γ point, currently the only supported k-point.

Memory is given in complex numbers (16 bytes each).

Notes on the combinations

JointDiagonalizationFunctional with OrbitalSubspace: the matrix elements $\langle \psi_m | \sigma_F | \psi_n \rangle$ are computed once from the overlap densities of all orbital pairs. Afterwards, each gradient evaluation is independent of the plane-wave basis and consists of $N_F$ matrix products of size $N \times N$. The practical limit is the memory of the overlap densities during the preparation.
